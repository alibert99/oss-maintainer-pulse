# Application Note

OpenAI's Codex for Open Source page says the program supports maintainers behind
critical open-source software. The public form asks for a public GitHub username,
a public repository URL, whether the applicant is a primary or core maintainer,
why the repository qualifies, and how API credits would be used.

Official page: <https://openai.com/form/codex-for-oss/>

## Important

Do not invent stars, downloads, users, maintainer role, or ecosystem importance.
A brand new repository is unlikely to qualify until it has real usage, active
maintenance, or clear importance to other open-source projects.

## Truthful 500-Character Draft

Use this only after replacing bracketed fields with accurate facts:

> Maintainer Pulse helps OSS maintainers turn GitHub issue and PR data into
> actionable triage, review-debt, stale-queue, and release-blocker reports. I am
> the [primary/core] maintainer. Current adoption: [stars/downloads/users]. It
> supports release and review workflows for [ecosystem/project audience].

## API Credits Draft

> I would use API credits to prototype maintainer automation: summarizing issue
> clusters, drafting release-checklist updates, spotting duplicate reports, and
> preparing review notes while keeping maintainers in control of final decisions.
